# Codex Batch 01 作業指示

更新日: 2026-07-17

この文書は、DOGAGAの初回実装・設計作業を複数のCodexセッションへ安全に分配するための指示書である。

## 0. 共通指示

各セッションは作業前に次を読む。

- `AGENTS.md`
- `README.md`
- `docs/PRODUCT_VISION.md`
- `docs/DEVELOPMENT_ROADMAP.md`
- `docs/ADR-001-DESKTOP-FIRST.md`
- `docs/ADR-002-JAPANESE-FIRST.md`
- 対象Issueに記載された関連文書

共通ルール:

- `main`へ直接コミットしない
- 対象Issue専用ブランチを作る
- 一つのセッションで複数Issueを混ぜない
- 実装範囲を勝手にMVP全体へ広げない
- UI文言と文書は日本語を正本とする
- 元素材を外部サービスへ送信しない
- 大容量メディアをGitへ入れない
- 未確定事項は推測で固定せず、PR本文またはIssueへ残す

## 1. 今すぐ並列で開始してよい作業

次の2件は、互いに同じ実装ファイルを変更しない前提で並列実行できる。

### Job A: Issue #5 — プロジェクトJSONスキーマ v0.1

目的:

- DOGAGAの保存形式を設計する
- 実装コードの土台となる型とサンプルを用意する

推奨ブランチ:

```text
docs/issue-5-project-format
```

最低成果物:

- `docs/PROJECT_FORMAT.md`
- `schemas/dogaga-project.schema.json` または同等のJSON Schema
- `examples/minimal-project.dogaga`
- `src/types/project.ts` を追加する場合は、アプリ基盤を勝手に大規模生成しない

重要判断:

- 内部時間単位を明示する
- 可変フレームレート素材でも破綻しない
- 元素材をJSONへ埋め込まない
- 素材未検出・再リンク状態を表現する
- 歌詞行と字幕クリップを表現する
- 将来のスキーマ移行を考慮する

禁止:

- UI実装
- クラウド保存
- バイナリ素材の埋め込み
- 独自の巨大フレームワーク導入

### Job B: Issue #4 — ブラウザ・コーデック対応表

目的:

- 初期対応形式と検証方法を決める
- Issue #2の実測結果を記録できる器を作る

推奨ブランチ:

```text
docs/issue-4-codec-matrix
```

最低成果物:

- `docs/CODEC_SUPPORT_MATRIX.md`
- 検証環境、素材条件、記録項目を含む表
- 自動判定と実機検証を区別した調査方法
- 対応、条件付き、非対応、未検証の状態定義
- テスト素材の取得・生成・ライセンス方針

Codexが実機を持たない環境では、実測値を捏造しない。

- 公式仕様またはAPI判定で確認した内容
- 実ブラウザで確認した内容
- 未検証の内容

を明確に分ける。

禁止:

- 「Chromeなら必ずH.264を書き出せる」などの未検証断定
- 権利不明素材の追加
- Issue #2の本体実装を同じPRへ混ぜる

## 2. Job Aマージ後に開始する作業

### Job C: Issue #6 — タイムライン編集コマンドとUndo / Redo

Issue #5のプロジェクトモデルを参照するため、Job AのPRがマージされた後に開始する。

推奨ブランチ:

```text
docs/issue-6-edit-command-model
```

最低成果物:

- `docs/EDIT_COMMAND_MODEL.md`
- TypeScriptインターフェース草案
- 基本編集操作の履歴例
- 歌詞タップ同期の履歴例
- 連続ドラッグの履歴圧縮方針
- 自動保存とUndo履歴の責務分離

特に確認すること:

- 一括オフセットを一回のUndoで戻せる
- タップ同期の誤操作を即座に戻せる
- trim / moveのドラッグ途中を大量履歴にしない
- コマンドがプロジェクト形式へ不自然な実装都合を持ち込まない

## 3. Job A・B・Cのレビュー後に開始する作業

### Job D: Issue #2 — 技術スパイク

これはBatch 01の中心だが、いきなり完成版編集アプリを作らない。

推奨ブランチ:

```text
feat/issue-2-media-spike
```

最初のPRは、次の縦一本に限定する。

1. React + TypeScript + Viteの最小アプリ
2. ローカルMP4ファイル選択
3. 動画の表示
4. 再生／停止／シーク
5. 素材メタデータ表示
6. 日本語のエラー表示
7. 検証手順をREADMEまたはdocsへ記録

次のPRで追加する候補:

- 音声波形
- トリム範囲指定
- 音付き書き出し
- 書き出し進捗
- OPFSキャッシュ

最初から全部を一つのPRにしない。

### 技術スパイクの判断記録

PR本文または `docs/TECH_SPIKE_RESULTS.md` に次を残す。

- 採用したライブラリとバージョン
- 選定理由
- ブラウザAPIだけで実現した部分
- 補助ライブラリが必要な部分
- コーデック、コンテナ、muxの責務
- 音声と映像の同期方法
- 時間単位
- メインスレッドとWorkerの分担
- メモリ上限への仮説
- 失敗した方法
- 次のPRへ持ち越すこと
