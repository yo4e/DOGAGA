# ADR-002: 日本語を正本として先行開発する

- Status: Accepted
- Date: 2026-07-17

## Context

DOGAGAの最初の利用者と初期開発・検証環境は日本語圏を中心とする。

DOGAGAは歌詞、字幕、文字演出を重要機能とするため、言語対応は単なるメニュー翻訳ではない。日本語には、次のような英語と異なる設計条件がある。

- 単語間スペースを前提にできない
- 句読点、括弧、全角・半角が混在する
- 改行位置が歌詞表現へ強く影響する
- 縁取り、字間、行間、縦書きなどの需要が高い
- 日本語フォントはファイルサイズやライセンス条件が大きい
- エラーや設定名を不自然な直訳にすると、初心者向けという製品目標を損なう

初期段階から日本語と英語を同時に完成させようとすると、未確定なUI文言の翻訳管理、画面幅差、レビュー負荷が増え、コア編集体験の検証が遅くなる。

一方、日本語だけを前提に文字列を各コンポーネントへ直接埋め込むと、将来の英語ローカライズが大規模な改修になる。

## Decision

DOGAGAのMVPは、**日本語を正本言語として先行開発する**。

### MVPで行うこと

- UI文言は日本語から設計する
- エラー、警告、オンボーディング、ヘルプ、アクセシビリティラベルも日本語を正本とする
- 仕様書、Issue、PR本文、開発メモは原則日本語で書く
- コード識別子、API、型、一般技術用語は英語を使用する
- UI文字列をメッセージカタログへ集約する
- 初期ロケールは `ja` または `ja-JP` のみでよい
- 日付、時刻、数値は `Intl` 等を利用し、ロケール依存処理を隔離する
- 外部字幕・歌詞ファイルはUTF-8を第一基準とする
- 日本語歌詞の行分割は改行を第一の境界とし、空白による単語分割を前提にしない
- 日本語フォントの出所、再配布、Web利用条件を記録する

### MVPで行わないこと

- 英語UIの完全翻訳
- 言語切替画面
- 多言語向けマーケティングサイト
- 機械翻訳だけで作った未レビュー文言の公開
- 全言語に共通する高度な禁則処理

## Implementation constraints

### 文字列管理

React等のコンポーネントへ表示文言を大量に直接記述しない。

初期段階では大規模なi18nフレームワークを必須としないが、最低限、次のような構造へ集約する。

```text
src/
  locales/
    ja.ts
```

または

```text
src/
  messages/
    ja.json
```

メッセージキーは表示文言そのものではなく、意味を示す安定した識別子にする。

```ts
export const ja = {
  common: {
    save: "保存",
    cancel: "キャンセル",
  },
  export: {
    start: "書き出す",
    failed: "動画を書き出せませんでした",
  },
};
```

### 日本語UI

- 不自然なカタカナ語を増やさない
- 専門用語が必要な場合は、初回表示やヘルプで説明する
- ボタン文言は操作結果が分かる動詞を優先する
- 「OK」だけで意味を担わせない
- エラーは原因、影響、次にできることを分ける
- 省略表示は日本語の可読性を確認する

### 歌詞・字幕

- 改行を作者の意図として尊重する
- 全角・半角を勝手に正規化して原文を破壊しない
- 正規化が必要な場合は検索・比較用の派生値として保持する
- ルビ、縦書き、禁則処理はMVP必須ではないが、将来追加を妨げないデータモデルにする
- SRT / VTT / LRCの読み書きで文字化けを検出または案内する

## English localization timing

英語ローカライズは、次の条件が揃った後に開始する。

- 日本語版で主要ワークフローが安定した
- 主要画面の構造と用語が大きく変わらない
- UI文字列がカタログへ集約されている
- 日本語のエラーとヘルプが一通り揃っている
- 翻訳対象の一覧を抽出できる

英語版では単純な逐語訳ではなく、英語圏の動画編集用語と初心者向け表現を再検討する。

## Consequences

### Positive

- 初期利用者に自然な体験を早く提供できる
- 日本語歌詞・字幕の扱いを製品の中心として磨ける
- 翻訳レビューに引っ張られず、コア機能へ集中できる
- 文字列集約により、将来の英語対応コストを抑えられる

### Negative

- 初期公開範囲は日本語利用者へ偏る
- 英語UIを前提とした外部テンプレートやサンプルをそのまま使いにくい
- 日本語フォントや行組みの検証負荷が増える
- 後の英語版でレイアウト差を調整する必要がある

## Revisit conditions

次の場合、この判断を再検討する。

- Public Betaで英語圏ユーザーを対象にする
- 海外サービス連携に英語UIが実質必須になる
- 英語圏のテスト利用者を継続的に確保できる
- 日本語版の主要ワークフローと用語が安定する
