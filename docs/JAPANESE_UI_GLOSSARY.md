# DOGAGA 日本語UI用語集・文体ガイド

- 状態: 初版
- 更新日: 2026-07-17
- 対象: Phase 0、Phase 1、歌詞タップ同期
- 関連Issue: #9

## 1. 目的

この文書は、DOGAGAのUI、エラー、ヘルプ、アクセシビリティラベルで使う日本語の正本である。同じ概念を実装者ごとに別の語で呼ばず、動画編集に不慣れな利用者にも、操作の結果と次にできることが伝わる状態を作る。

コード識別子、API名、型名、開発者向けログは一般的な英語を使う。日本語の表示名へ合わせるために、既に通用している技術識別子を不自然に翻訳しない。

この文書の「採用語」は、ユーザーへ表示する新しい文言で優先する語を示す。既存の設計文書に現れる英語の技術名や説明上の言い換えまで禁止するものではない。ただし、同じ画面や同じ操作フローでは採用語に統一する。

対象範囲:

- Phase 0: 素材の読み込み、再生、再生位置の移動、波形、書き出し、保存、復旧、再リンク
- Phase 1: 素材一覧、タイムライン、基本編集、音声、文字、トランジション
- 歌詞タップ同期: 歌詞取り込み、同期モード、タイミング修正、全体・範囲の時間移動

英語UIの翻訳、言語切替画面、i18nライブラリの選定、実装コンポーネントの設計はこの文書の対象外とする。

## 2. 用語を選ぶ原則

1. 一つの概念には一つの採用語を割り当てる。
2. ボタンには、押した後の結果が分かる動詞を使う。
3. 動画編集で広く使われ、日本語へ置き換えると意味が曖昧になる語はカタカナで採用する。
4. カタカナ語を採用するときは、初回表示、ツールチップ、またはヘルプで短く説明する。
5. 初心者向けの表示名と、技術ログの識別子を分ける。
6. 「データ」「処理」「失敗」のように対象や結果が分からない語を単独で使わない。
7. 日本語歌詞は改行を第一の境界とし、単語間スペースがある前提の文言や操作を作らない。
8. 原因を確認できていないときは推測を表示せず、「原因を特定できませんでした」と明記する。

### 2.1 カタカナ語を採用する条件

次のいずれかを満たし、短い日本語へ置き換えると別概念と混同する場合に採用する。

- 動画編集で一般的に使われる: `クリップ`、`トラック`、`タイムライン`
- DOGAGA内の操作対象を短く一意に表せる: `スナップ`、`クロスディゾルブ`
- 外部仕様との対応関係が重要である: `コーデック`、`キャッシュ`

一般的な日本語で結果を明確に示せる場合は、日本語を優先する。たとえば、`エクスポート`ではなく`書き出し`、`インポート`ではなく文脈に応じて`読み込み`または`取り込み`を使う。

## 3. 基本概念とファイル操作

| 採用語 | 避ける語 | 説明・使用例 |
| --- | --- | --- |
| プロジェクト | 編集データ、セッション、ドキュメント | 素材への参照と編集内容、設定をまとめた作業単位。元素材そのものは含まない。例: `プロジェクトを開く` |
| プロジェクトファイル | プロジェクトデータ、JSONファイル | 保存や移動に使うDOGAGAのファイル。実装形式を通常UIへ出す必要はない。例: `プロジェクトファイルを保存` |
| 素材 | メディア、アセット、ソース | 編集に使う動画、画像、音声の総称。ユーザー向け一覧は`素材`または`素材一覧`とする。技術ログでは`asset`を使ってよい。 |
| クリップ | 素材、シーン、オブジェクト | 素材をタイムラインへ配置した区間。同じ素材から複数のクリップを作れる。素材と同義にしない。 |
| トラック | レイヤー、段、レーン | タイムライン上でクリップを並べる横方向の領域。重なり順を説明するときだけ`上のトラック`など位置を添える。 |
| タイムライン | 編集画面、時間軸バー | 時間に沿ってクリップ、歌詞、再生位置を確認・編集する領域。 |
| 再生ヘッド | 再生カーソル、シークバー、現在位置線 | 現在の再生位置を示す線やマーカー。時刻そのものは`再生位置`と呼ぶ。 |
| プレビュー | 確認画面、モニター、再生画面 | 編集途中の見た目と音を確認する表示。完成ファイルではないことを必要に応じて説明する。 |
| 読み込む | インポート、開く、ロードする | 動画、画像、音声、プロジェクトファイルをDOGAGAで利用可能にする。ボタンは対象を含めて`素材を読み込む`とする。 |
| 取り込む | インポート、読み込む（歌詞本文） | 歌詞や字幕の本文を行へ変換して編集対象にする。例: `歌詞を取り込む`。ファイルを選ぶ操作だけを指す場合は`読み込む`を使う。 |
| 保存 | セーブ、記録 | プロジェクトの編集内容を保持する。完成動画の生成には使わない。例: `プロジェクトを保存しました` |
| 自動保存 | オートセーブ、バックアップ | 編集内容をユーザー操作なしで保存する仕組み。復旧用の世代保存と同義にしない。 |
| 再開 | 復元、ロード | 保存したプロジェクトを開き、編集を続けられる状態にする。例: `前回の編集を再開` |
| 復旧 | 復元、リカバリー、再開 | 異常終了や保存失敗の後に、残っている編集内容を利用可能な状態へ戻す。通常のプロジェクト再開には使わない。 |
| 素材を再リンク | 再接続、再読込、差し替え | 見つからない元ファイルをユーザーが選び直し、既存の編集内容へつなぎ直す。初回は`元のファイルを選び直して、編集内容につなぎ直します`と説明する。 |
| 一時データ | テンポラリ、作業データ | サムネイルや波形など、削除しても元素材やプロジェクトを失わず再生成できるデータ。詳細設定では`一時データ（キャッシュ）`と併記してよい。 |
| キャッシュ | 一時ファイル、保存データ | 開発者向け説明や詳細設定で使う技術用語。通常画面では`一時データ`を優先する。プロジェクトの保存内容と同義にしない。 |
| 書き出し | エクスポート、出力、保存 | 完成動画、静止画、字幕ファイルを新しいファイルとして生成する。ボタンは`書き出す`、画面名は`書き出し`とする。 |
| 書き出し設定 | エクスポート設定、出力設定 | 形式、サイズ、画質など、完成ファイルの生成条件。用途プリセットを先に見せる。 |

### 3.1 「保存」と「書き出し」の境界

- `保存`: 後で編集を続けるためにプロジェクトを保持する。
- `プロジェクトファイルを保存`: `.dogaga`を端末上のファイルとして保持する。
- `書き出し`: 視聴・投稿・受け渡しに使う動画、画像、字幕ファイルを生成する。

同じダイアログ内で`保存`と`書き出し`を混在させない。書き出し後も編集用プロジェクトが別に残ることを、初回利用時に説明する。

## 4. 再生・形式・状態

| 採用語 | 避ける語 | 説明・使用例 |
| --- | --- | --- |
| 再生 | プレイ、プレビューする | 素材またはタイムラインを時間に沿って表示・発音する。ボタンは状態に応じて`再生`と`停止`を切り替える。 |
| 停止 | ポーズ、一時停止（通常再生） | 通常の再生を止め、現在位置を保つ。歌詞同期モードの中断だけは`同期を一時停止`とする。 |
| 再生位置 | シーク位置、現在時刻 | 現在確認しているタイムライン上の時刻。ユーザー向けUIでは`シーク`を動詞として使わない。 |
| 再生位置を移動 | シークする、飛ぶ | 再生ヘッドを別の時刻へ動かす操作。短いツールチップでは`10秒進む`のように結果を示す。 |
| 波形 | オーディオ波形、音声グラフ | 音の大きさの変化を時間に沿って示す表示。視覚情報だけに依存しない。 |
| ファイル形式 | フォーマット、拡張子 | MP4、PNG、WAVなど、利用者が選択や確認に使う形式。拡張子だけでコーデックを断定しない。 |
| コーデック | 形式、エンコーダー | 映像や音声の符号化方式。対応可否の詳細や開発者向け情報で使用し、必要なら`映像コーデック`、`音声コーデック`と対象を付ける。 |
| 対応 | サポート、利用可 | DOGAGAで検証済みの操作ができる状態。未検証を`対応`と表示しない。 |
| 条件付きで対応 | 一部対応、たぶん利用可 | ブラウザ、OS、コーデックなど明示した条件で利用できる状態。条件を同じ場所に表示する。 |
| 非対応 | 未対応、利用不可 | 現在のDOGAGAでは利用できないことを確認した状態。可能なら対応形式や変換など次の操作を案内する。 |
| 未確認 | 未対応、非対応 | まだ検証できていない状態。確認できていないことと、利用できないことを混同しない。 |

## 5. タイムラインと基本編集

| 採用語 | 避ける語 | 説明・使用例 |
| --- | --- | --- |
| 選択 | アクティブ化、フォーカス | 操作対象を指定すること。キーボードフォーカスとは別概念なので、アクセシビリティ実装では区別する。 |
| 追加 | 挿入、配置（ボタン名） | 素材や文字をプロジェクトへ加える操作。位置を明示するときは`タイムラインに追加`とする。 |
| 移動 | 動かす、スライド | クリップや再生ヘッドの位置を変える。ドラッグ中の案内では`移動`に統一する。 |
| トリム | トリミング、切り抜き、カット | クリップが使う素材範囲を、端を動かして短くまたは長くする。初回は`クリップの端を動かして、使う範囲を調整します`と説明する。 |
| 分割 | カット、切断、スプリット | 一つのクリップを再生ヘッド位置で二つに分ける。ボタンは`再生ヘッド位置で分割`とする。 |
| 複製 | コピー、コピーを作成、クローン | 選択した要素と同じ内容をもう一つ作る。クリップボードへ入れる`コピー`とは区別する。 |
| 削除 | 消去、除去、捨てる | プロジェクトから選択要素を取り除く。元素材ファイルを端末から消さない場合は、その旨を破壊的操作の案内に含める。 |
| 元に戻す | 取り消す、Undo、戻る | 直前の編集操作を一段階戻す。可能なら`分割を元に戻す`のように対象操作を通知する。 |
| やり直す | Redo、元に戻すを戻す | `元に戻す`で取り消した編集操作を再適用する。 |
| スナップ | 吸着、磁石、位置合わせ | クリップ端などを再生ヘッド、別のクリップ端、マーカーへ自動で合わせる動作。設定は`スナップ`、補足は`近くの位置に自動で合わせます`とする。 |
| ギャップを削除 | 空白を詰める、間を削除 | クリップ間の空き時間をなくし、後続クリップを手前へ移動する。削除対象が素材でないことを明確にする。 |
| トランジション | 切り替え、場面転換、効果 | クリップの境界で映像や音を切り替える方法の総称。初回は`クリップの切り替わり方`と説明する。 |
| カット | 切断、分割 | トランジションを置かず、クリップ境界で直接切り替える方法。編集操作の`分割`には使わない。 |
| クロスディゾルブ | ディゾルブ、クロスフェード | 前後の映像を重ねながら切り替えるトランジション。音声の重なりを指す場合は`クロスフェード`と区別する。 |
| フェードイン | フェード、出現 | 黒、白、無音などの基準状態から徐々に映像または音を現す。対象が曖昧なら`映像のフェードイン`とする。 |
| フェードアウト | フェード、消える | 映像または音を基準状態へ徐々に変化させる。対象と到達状態を必要に応じて示す。 |
| ミュート | 消音、音をオフ | 対象トラックまたはクリップの音を一時的に出さない。削除や音量0への恒久変更と同義にしない。 |
| 音量 | ボリューム、ゲイン（通常UI） | 聞こえる大きさの設定。技術的な増幅値が必要な詳細設定では`ゲイン`を使ってよい。 |
| キャンバス | 画面、ステージ、フレーム | 書き出される映像の縦横比と表示領域。初回は`完成動画に入る範囲`と説明する。 |
| 縦横比 | アスペクト比、比率 | `16:9`、`9:16`、`1:1`などキャンバスの縦横の比率。 |

## 6. 歌詞、字幕、文字

`歌詞`、`字幕`、`テロップ`、`テキスト`は同義語にしない。

| 採用語 | 避ける語 | 説明・使用例 |
| --- | --- | --- |
| 歌詞 | 字幕、テロップ（歌詞の意味で） | 楽曲の言葉を表す本文。歌詞動画と歌詞同期の画面では一貫して`歌詞`を使う。 |
| 歌詞行 | テロップ、字幕ブロック、センテンス | 改行で区切られた一つの歌詞単位。日本語を空白で単語分割しない。 |
| 字幕 | 歌詞、テロップ | 開始・終了時刻を持ち、映像へ表示またはSRT / VTT等で受け渡す文字情報。歌詞から生成された結果を形式の観点で説明するときは`歌詞の字幕ファイル`とする。 |
| テロップ | 字幕、歌詞、テキスト | タイトル、名前、補足など、画面上に演出付きで置く文字。時刻付き発話本文の総称にはしない。 |
| テキスト | 文字、字幕 | タイトルやクレジットを含む一般の文字要素。歌詞専用画面では`歌詞`を優先する。 |
| 歌詞を取り込む | 歌詞をインポート、字幕を作る | 貼り付けた本文や対応ファイルを、編集できる歌詞行へ変換する。 |
| 行を分割 | 文を分ける、字幕を分割 | カーソル位置で一つの歌詞行を二つへ分ける。クリップの`分割`と同じ画面にある場合は対象を付ける。 |
| 上の行と結合／下の行と結合 | マージ、連結 | 選択した歌詞行を隣接行と一つにする。結合先をボタン名で明示する。 |
| 取り込み時の歌詞 | Original Lyrics、原文データ | 取り込み直後に保持する変更前の本文。`元の歌詞と比較`、`取り込み時の歌詞に戻す`と表示する。 |

## 7. 歌詞同期

| 採用語 | 避ける語 | 説明・使用例 |
| --- | --- | --- |
| タップ同期 | タイミング打ち、手動同期、タップ入力 | 再生しながらキーを押し、歌詞行の開始時刻を順に記録する機能名。 |
| タップ同期モード | 同期画面、記録モード | Spaceキーを行頭記録へ割り当てる専用状態。通常編集との違いを画面の見た目と説明で示す。 |
| 同期する | 合わせる、タイミングを付ける | 歌詞行と楽曲上の時刻を対応付ける操作。`同期`は処理または結果に使う。 |
| タイミング | 同期、位置、時間 | 歌詞行の開始・終了時刻。個別調整は`タイミングを調整`とする。同期機能全体の名称には使わない。 |
| 同期済み | 完了、済、設定済み | 歌詞行に有効な開始時刻が記録された状態。色だけで区別しない。 |
| 未同期 | 未設定、未完了、空 | まだ開始時刻が記録されていない状態。 |
| 現在の行 | アクティブ行、対象行 | タップ同期で次に時刻を記録する歌詞行。表示と読み上げの両方で位置を示す。 |
| 開始時刻 | 行頭、イン点 | 歌詞行の表示を始める時刻。`行頭`は説明文で使用できるが、入力欄ラベルは`開始時刻`とする。 |
| 終了時刻 | アウト点、終端 | 歌詞行の表示を終える時刻。 |
| タップ遅延補正 | レイテンシー、オフセット補正 | キーを押す遅れを記録時刻へ反映する設定。値の符号だけに頼らず、`80ミリ秒前`のような結果も表示する。 |
| カウントイン | 前カウント、予備再生 | タップ同期の記録開始前に出す合図。初回に`記録前に3秒数えます`と説明する。 |
| 全体をずらす | 一括オフセット、全体シフト、タイミング補正 | 全歌詞行を同じ時間だけ前後へ動かす操作。入力欄は`移動量`、結果は`120ミリ秒前へ移動`と示す。 |
| この行以降をずらす | 範囲オフセット、以降をシフト | 選択行から最後までを同じ時間だけ前後へ動かす操作。DOGAGAの主要操作なのでメニューの奥へ隠さない。 |
| 同期を一時停止 | 終了、キャンセル、モード解除 | 再生を止め、現在行と同期結果を保持したまま専用モードを中断する。 |
| 続きから再開 | 再同期、再実行 | 保持した現在行からタップ同期を続ける。 |
| 同期をやり直す | リセット、再同期 | 選択した範囲の既存時刻を置き換えて再度記録する。対象範囲と戻せるかを事前に示す。 |

### 7.1 時間移動の表示

`-120ms`だけでは、前後どちらへ動くか判断しにくい。数値入力には符号を残してよいが、確認文と実行後通知では結果を言葉で示す。

- `-120ms（120ミリ秒前）`
- `+300ms（300ミリ秒後）`
- `30行を120ミリ秒前へ移動しました`

## 8. 表示名と技術ログを分ける

ユーザー向け表示は操作と復帰を説明し、技術ログは調査に必要な事実を記録する。例外メッセージ、エラーコード、API名をそのままユーザーへ表示しない。

| 概念 | ユーザー向け表示 | コード・ログの例 |
| --- | --- | --- |
| 素材 | 素材、動画素材、音声素材 | `asset`, `assetId`, `AssetNotFoundError` |
| 素材一覧 | 素材 | `mediaLibrary`, `assetList` |
| 再生位置を移動 | 10秒進む、指定位置へ移動 | `seek`, `targetTimeUs` |
| 素材を再リンク | 素材を再リンク | `relinkAsset`, `MissingAsset` |
| 一時データ | 一時データ（キャッシュ） | `cache`, `opfsCache` |
| 書き出し | 書き出す | `export`, `VideoEncoder`, `mux` |
| 全体をずらす | 全体をずらす | `ShiftAllCaptions`, `offsetUs` |
| この行以降をずらす | この行以降をずらす | `ShiftCaptionRange`, `startLineId` |

### 8.1 ユーザー向けエラーに含めるもの

- 何ができなかったか
- 確認できた原因、または原因を特定できなかったこと
- 編集内容や元素材への影響
- 次にできる操作
- 問い合わせや調査に必要な場合だけ、展開可能な`詳細`とエラーID

### 8.2 開発者向けログに含めるもの

- 安定したエラーコード
- 失敗した操作名
- ブラウザ、OS、利用API
- 素材ID、コンテナ、コーデック、解像度、サイズなど必要最小限のメタデータ
- 内部時刻は単位を含むフィールド名で記録する。例: `targetTimeUs`
- 原因となった例外とスタック（開発環境または許可された診断情報）

歌詞本文、音源内容、動画フレーム、端末上の完全なファイルパスを外部ログへ送信しない。ファイル名など個人情報になり得る値も、明示同意のない外部送信では省く。ユーザー向け文言へ内部スタックを埋め込まない。

## 9. UI文体

### 9.1 共通

- 短いラベルとボタンは常体の名詞または動詞にする: `再生`、`書き出す`。
- 説明、ツールチップ、エラー本文、アクセシビリティ用の補足は`です・ます`調にする。
- 利用者を責める表現を使わない: `無効なファイルを選びました`ではなく`このファイル形式には対応していません`。
- `〜してください`を連続させず、次の操作をボタンでも示す。
- 半角英数字を基本とし、単位との間に不要な空白を入れない: `1080p`、`120ミリ秒`、`30fps`。
- 処理中は一文字の三点リーダー`…`を使う: `書き出しています…`。
- `成功しました`だけで終えず、対象と結果を示す: `動画を書き出しました`。

### 9.2 ボタン

- 押した結果が分かる動詞を使う: `素材を読み込む`、`書き出す`、`素材を再リンク`。
- `OK`、`はい`、`実行`だけに意味を担わせない。
- 同じ画面で動詞の形を揃える: `保存`と`キャンセル`、または`保存する`と`キャンセルする`を混在させない。
- 破壊的操作は対象を含める: `クリップを削除`、`一時データを削除`。
- 戻れる操作を過度に危険表示しない。Undoできる削除は通知で`元に戻す`を提供する。

### 9.3 メニュー

- 頻繁な操作は短い動詞で揃える: `分割`、`複製`、`削除`。
- 対象が複数あり得る場合は対象を付ける: `歌詞行を分割`、`クリップを分割`。
- ショートカットは文言の一部へ埋め込まず、別の列または補足として表示する。
- 省略記号だけで別画面が開くことを伝えず、必要なら`書き出し設定を開く`のように結果を書く。

### 9.4 ツールチップとヘルプ

- ツールチップは操作結果を一文で説明する: `再生ヘッド位置でクリップを二つに分けます。`
- 初出の専門語は短い説明を付ける: `スナップをオンにすると、クリップ端が近くの位置へ自動で合います。`
- キーだけに依存せず、意味を先に書く: `再生／停止（Space）`。
- 表示中の状態と異なる一般説明を出さない。

### 9.5 ダイアログ

ダイアログは、タイトル、本文、操作の順に読むだけで判断できるようにする。

- タイトル: 何が起きるか、または何ができなかったか。
- 本文: 対象、影響、戻せるか、必要なら原因。
- 主操作: 具体的な動詞。`削除`ではなく`一時データを削除`。
- 副操作: `キャンセル`、`あとで`、`編集に戻る`など、戻り先を明確にする。
- 元素材を端末から消さない場合は、その事実を本文で示す。
- 取り消せない操作では`この操作は元に戻せません`を操作前に示す。

例:

```text
一時データを削除しますか？

波形とサムネイルを削除します。元の素材とプロジェクトは削除されません。
必要になったときに一時データを作り直すため、次の表示に時間がかかる場合があります。

[キャンセル] [一時データを削除]
```

### 9.6 アクセシビリティ

- 表示ラベルとアクセシブルネームで同じ採用語を使う。
- アイコンだけのボタンは、見た目ではなく結果を読む: `分割`、`10秒進む`。`ハサミアイコン`とはしない。
- 状態を含める: `スナップ、オン`、`4行目、未同期、現在の行`。
- 色、波形、位置だけに意味を依存させない。
- ショートカットを使わなくても同じ操作へ到達できるようにする。
- 処理開始、進捗、完了、失敗をライブリージョン等で通知する。進捗を毎フレーム読み上げず、意味のある間隔にする。
- 破壊的操作の確認では、フォーカスを安全側の操作へ置く。

アクセシビリティラベル例:

```text
再生
停止
再生位置、42秒120ミリ秒
スナップ、オン
4行目、未同期、現在の行
書き出し、42パーセント
```

## 10. エラーメッセージ原則

### 10.1 基本構造

エラーは、見出しだけで失敗した操作を特定でき、本文に`原因`、`影響`、`次の操作`を含める。

```text
タイトル: {対象}を{操作}できませんでした

原因: {確認できた原因／原因を特定できなかったこと}
影響: {保存内容、元素材、進行中の操作への影響}
次の操作: {復帰に必要な一つ以上の具体的な行動}

[副操作] [主操作]
詳細: {エラーID。必要な場合だけ技術情報を展開}
```

ラベル`原因:`などを実画面へ必ず表示する必要はない。ただし、三要素は読む順序で判別できる文章にする。

### 10.2 原因を断定する条件

- API結果、容量確認、形式解析などで確認できた事実だけを原因として表示する。
- 拡張子だけを見て`コーデックが非対応`と断定しない。
- 原因候補が複数ある場合は、推測を一つに絞らず確認方法を案内する。
- 技術ログに例外があるだけで、ユーザーの操作ミスと表現しない。

### 10.3 取り消し可能性

- Undoできる操作: 完了通知に`元に戻す`を用意し、原則として事前確認を増やさない。
- Undoできないが元素材へ影響しない操作: 失われる対象と再生成できるかを確認前に示す。
- 元ファイルや復旧できない内容へ影響する操作: 対象、影響、戻せないことを操作前に明示する。
- 失敗時: どこまで完了したか、編集内容や途中ファイルが残るかを示す。

## 11. エラーテンプレート

### 11.1 素材が見つからない

```text
素材が見つかりません

このプロジェクトで使っている元のファイルを確認できませんでした。
編集内容は残っていますが、この素材を使う部分はプレビューと書き出しができません。
元のファイルを選び直して、素材を再リンクしてください。

[あとで] [素材を再リンク]
```

### 11.2 非対応形式

```text
この素材を読み込めませんでした

このファイルの映像形式には現在対応していません。
プロジェクトと元のファイルは変更されていません。
対応形式を確認するか、対応する形式へ変換してからもう一度読み込んでください。

[対応形式を確認] [別の素材を選ぶ]
```

形式を解析できなかった場合は、`対応していません`と断定せず、`ファイル形式を確認できませんでした`へ差し替える。

### 11.3 ファイルが壊れている、または読み取りに失敗した

```text
この素材を読み込めませんでした

ファイルの内容を最後まで読み取れませんでした。ファイルが壊れているか、読み取り権限がない可能性があります。
プロジェクトと元のファイルは変更されていません。
元のアプリで再生できるか確認するか、別のファイルを選んでください。

[別の素材を選ぶ] [もう一度試す]
```

### 11.4 保存容量不足

```text
動画を書き出せませんでした

保存先の空き容量が不足しています。
書き出し途中のファイルは完成していません。プロジェクトと元の素材は残っています。
空き容量を増やすか、別の保存先を選んでからもう一度書き出してください。

[書き出し設定に戻る] [保存先を選び直す]
```

必要容量を信頼できる方法で算出できた場合だけ、`あと約{requiredSpace}`のように表示する。

### 11.5 書き出し失敗（原因不明）

```text
動画を書き出せませんでした

書き出しを完了できませんでしたが、原因を特定できませんでした。
プロジェクトと元の素材は残っています。完成していない途中ファイルは使用できません。
設定を変えずにもう一度試してください。繰り返し失敗する場合は、エラーIDを添えて報告してください。

[詳細を表示] [もう一度書き出す]
```

### 11.6 プロジェクト保存失敗

```text
プロジェクトを保存できませんでした

保存先へ書き込めませんでした。
前回の保存以降の編集内容は、このタブを閉じると失われる可能性があります。元の素材は変更されていません。
別の保存先を選ぶか、プロジェクトファイルをもう一度保存してください。

[編集に戻る] [保存先を選び直す]
```

### 11.7 歌詞ファイルの文字コードを確認できない

```text
歌詞を取り込めませんでした

歌詞ファイルをUTF-8のテキストとして読み取れませんでした。
現在の歌詞とタイミングは変更されていません。
UTF-8で保存し直すか、歌詞本文を貼り付けてください。

[貼り付けに切り替える] [別のファイルを選ぶ]
```

### 11.8 同期モードの安全な中断

ウィンドウが非アクティブになった場合は、失敗扱いではなく状態通知にする。

```text
タップ同期を一時停止しました

DOGAGAのウィンドウが操作対象から外れたため、誤記録を防ぐために停止しました。
記録済みのタイミングと現在の行は残っています。

[同期を終了] [続きから再開]
```

## 12. メッセージキー

### 12.1 命名規則

メッセージキーは英語の意味識別子とし、表示文言、画面上の位置、現在の部品構造から独立させる。

```text
<domain>[.<subject>].<role>.<semanticName>[.<part>]
```

- 区切りは`.`、各区分は英語のlowerCamelCaseを使う。
- `domain`は`project`、`media`、`timeline`、`export`、`lyrics`など安定した機能領域にする。
- 複数領域で同じ意味を共有する`common`では、`subject`を省略してよい。
- `role`は`action`、`label`、`status`、`help`、`dialog`、`error`、`a11y`など用途を表す。
- タイトル、本文、ボタンが別々に必要なら末尾を`title`、`body`、`primaryAction`などに分ける。
- エラーコードとメッセージキーを分ける。表示文言の変更で監視集計の識別子を変えない。
- 変数名は英語で意味と単位を示す: `{fileName}`、`{requiredSpace}`、`{offsetMs}`。
- 日本語文を連結する小片ではなく、一文または一つのUI要素を一キーにする。将来の英語で語順を変更できるようにする。

避ける例:

```text
button.ok
dialog2.message
leftPanel.missing
error.unknown
動画を書き出せませんでした
lyrics.shift.prefix
```

採用例:

```text
common.action.cancel
project.save.status.completed
project.save.error.writeFailed.title
project.save.error.writeFailed.body
media.import.action.selectFile
media.import.error.unsupportedFormat.title
media.relink.action.start
media.relink.error.assetMissing.body
timeline.clip.action.splitAtPlayhead
timeline.snap.a11y.enabled
export.video.action.start
export.video.status.progress
export.video.error.insufficientStorage.body
export.video.error.failedUnknown.primaryAction
lyrics.import.error.invalidEncoding.body
lyrics.sync.action.start
lyrics.sync.action.pause
lyrics.sync.action.resume
lyrics.sync.status.active
lyrics.sync.a11y.currentUnsyncedLine
lyrics.timing.action.shiftAll
lyrics.timing.action.shiftFromSelectedLine
```

### 12.2 カタログ例

```ts
export const ja = {
  export: {
    video: {
      action: {
        start: "書き出す",
      },
      status: {
        progress: "動画を書き出しています… {progress}%",
      },
      error: {
        insufficientStorage: {
          title: "動画を書き出せませんでした",
          body: "保存先の空き容量が不足しています。空き容量を増やすか、別の保存先を選んでください。",
        },
      },
    },
  },
  lyrics: {
    timing: {
      action: {
        shiftAll: "全体をずらす",
        shiftFromSelectedLine: "この行以降をずらす",
      },
    },
  },
} as const;
```

実装時にフラットキーとネスト構造のどちらを採用してもよいが、同じ命名規則から機械的に相互変換できるようにする。

### 12.3 キー再利用

- `キャンセル`のように意味も振る舞いも同じ操作は`common.action.cancel`を再利用できる。
- 同じ日本語でも意味が異なる場合は別キーにする。通常再生の`停止`と同期モードの`同期を一時停止`を一キーにしない。
- 見えるラベルだけでは読み上げ時の文脈が足りない場合、アクセシビリティ用キーを別に用意する。

## 13. 既存文書との整合

確認対象:

- `README.md`
- `docs/PRODUCT_VISION.md`
- `docs/DEVELOPMENT_ROADMAP.md`
- `docs/ADR-001-DESKTOP-FIRST.md`
- `docs/ADR-002-JAPANESE-FIRST.md`
- `docs/LYRIC_SYNC_UX.md`
- `docs/CODEX_BATCH_01.md`

既存文書との用語境界は次のように解釈する。

- `メディア一覧`は開発上の機能名として現れる。新しいユーザー向け画面名は`素材`または`素材一覧`とする。
- `トリミング`は説明文に現れる。新しいUIの操作名は`トリム`に統一する。
- `テロップ候補`や`字幕一覧`は一般の文字・字幕機能を説明する箇所に現れる。歌詞タップ同期画面では`歌詞行`、`歌詞一覧`を使う。
- `エクスポート設定`、`エクスポート前チェック`は設計文書の説明語として現れる。ユーザー向け表示は`書き出し設定`、`書き出し前チェック`とする。
- `一括オフセット`、`全体オフセット`は技術概念として現れる。主要操作の表示名は`全体をずらす`、入力欄は`移動量`とする。
- `遅延補正`は同期画面案に現れる。設定の正式名は対象を明確にした`タップ遅延補正`とする。
- `Original Lyrics`はデータモデル上の概念として残せる。ユーザー向け表示は`取り込み時の歌詞`とする。

以上は概念の変更ではなく、既存仕様にある初心者向け表示と技術用語を分離するものなので、`ADR-002-JAPANESE-FIRST.md`および歌詞同期の操作仕様と矛盾しない。

- [ ] ボタンだけを読んでも操作結果が分かる

## 15. 用語を追加・変更するとき

1. 既存の採用語で表せない概念かを確認する。
2. 同じ概念の別名を追加せず、採用語、避ける語、説明を更新する。
3. メッセージキーは表示文言の変更だけでは改名しない。
4. 動画編集の技術概念を変える場合は、関連するIssueまたはADRへ理由を残す。
5. 歌詞の語を変更する場合は、`docs/LYRIC_SYNC_UX.md`との整合を確認する。
6. 実装で使われる文言は、画面種別ごとの文体とアクセシビリティを合わせてレビューする。
