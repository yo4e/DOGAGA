# DOGAGA 開発ロードマップ

更新日: 2026-07-17

## 1. 開発戦略

DOGAGAは、最初から完全な動画編集アプリを作らない。

優先するのは機能の横展開ではなく、**素材を選ぶところから一本の動画を書き出すまでの縦の流れ**である。

不確実性は次の順に潰す。

1. ブラウザで、実用的な速度と画質で再生・編集・書き出しができるか
2. プレビューと書き出し結果を一致させられるか
3. 保存、再開、素材の再リンクが壊れないか
4. タイムライン操作が気持ちよく成立するか
5. 歌詞同期が既存ツールより速く感じられるか
6. 実際のMV、PV、Short、Canvas制作で使えるか
7. その後に自動字幕、ビート解析、AI、クラウド機能を足す

## 2. DOGAGAが最初に完成させる三本

MVPの成否は、次の三つを実制作で完成できるかで判断する。

### 2.1 60秒の楽曲PV

- 10本程度の動画／画像
- 1本の楽曲
- カット、トリム、並べ替え
- クロスディゾルブ
- タイトルと短い文字
- 音量、フェード
- 9:16または16:9
- 1080p書き出し

### 2.2 一曲分の歌詞動画

- 正しい歌詞を貼り付ける
- 行へ分割する
- 再生しながらキーで同期する
- 全体ずれと途中以降のずれをまとめて直す
- 文字スタイルを一括適用する
- 字幕焼き込みまたは字幕ファイルを書き出す

### 2.3 Spotify Canvas

- 3〜8秒
- 9:16
- ループ継ぎ目確認
- セーフエリアと点滅警告
- Canvas条件に合うMP4を書き出す

この三本に直接つながらない機能は、原則としてMVP後へ送る。

## 3. 対象環境と初期制限

### 初期対象

- デスクトップ
- macOS + Chrome最新版を第一基準
- Windows + Chrome / Edgeを第二基準
- 720p / 1080p
- 30fpsを基本
- 完成尺は一曲分、おおむね10分まで
- H.264 / AAC MP4を第一対象
- PNG / JPEG / MP3 / WAVを主要素材とする

### 後回し

- スマートフォンでの本格編集
- Safari / Firefoxの完全対応
- 4Kの安定書き出し
- 長編映画、長時間配信素材
- 大量トラック
- 高度なカラーグレーディング
- 複雑なキーフレーム
- 万能なコーデック変換

制限は隠さず、素材読み込み時と書き出し時に明示する。

## 4. 技術方針

### 4.1 初期構成候補

- UI: React + TypeScript
- ビルド: Vite
- デコード／エンコード: WebCodecs
- コンテナ解析／多重化: 専用ライブラリを比較検証
- プレビュー合成: Canvas 2Dから開始
- 音声再生／解析: Web Audio API
- 重い処理: Web Workers
- 作業キャッシュ: OPFS
- メタデータ: IndexedDB
- プロジェクト形式: バージョン付きJSON
- 補助変換: ffmpeg.wasmを限定的に検証
- 単体テスト: Vitest
- ブラウザテスト: Playwright

WebCodecsは低レベルで高速な映像／音声処理を可能にする一方、ブラウザ間で利用できるコーデックが同一とは限らない。DOGAGAは入力形式を明確に絞り、万能変換を目指さない。

### 4.2 設計上の四原則

#### プレビューと書き出しを別物にしない

- 同じProjectモデルを使う
- 同じタイミング計算を使う
- 同じエフェクトパラメータを使う
- プレビュー専用の近似処理を使う場合は明記する

#### 編集操作をコマンド化する

すべてのユーザー編集を、Undo / Redo可能なコマンドとして扱う。

例:

- AddClip
- MoveClip
- TrimClip
- SplitClip
- DeleteClip
- AddTransition
- UpdateTextStyle
- SetCaptionTiming
- ShiftCaptionRange

#### 元素材を複製しない

- 編集は非破壊
- プロジェクトは素材参照と編集指示を保存する
- 波形、サムネイル、プロキシだけをキャッシュする

#### ローカルだけでも完成できる

- コア編集はログインなしで動く
- 元素材をサーバーへ必須送信しない
- 外部AIを使わなくても動画を完成できる

## 5. プロジェクトモデル

最低限、次の構造を持つ。

```text
Project
├─ version
├─ canvas
│  ├─ width
│  ├─ height
│  ├─ fps
│  └─ duration
├─ assets[]
│  ├─ id
│  ├─ kind
│  ├─ fingerprint
│  ├─ metadata
│  └─ relinkHints
├─ tracks[]
│  ├─ video clips
│  ├─ audio clips
│  └─ text/caption clips
├─ markers[]
├─ styles[]
├─ exportPreset
└─ metadata
```

### 素材参照

ブラウザの一時的なFileオブジェクトだけへ依存しない。

- アセットID
- ファイル名
- サイズ
- 更新日時
- duration
- codec / container
- 先頭／末尾の部分ハッシュ等

を使い、プロジェクト再開時に素材を再リンクできるようにする。

### プロジェクトファイル

- 拡張子候補: `.dogaga`
- 実体: バージョン付きJSON、必要ならZIPコンテナ化
- 元動画／音声は原則として含めない
- 将来のマイグレーション関数を用意する
- 未知の新バージョンを無理に開かない

v0.1の時間単位、再リンク、歌詞、移行の詳細は `docs/PROJECT_FORMAT.md` を正本とする。

## 13. AI機能の導入順

AIはMVP後に、明確な時間短縮が見込めるものから試す。

1. 音声からの字幕候補生成
2. 既存歌詞と歌唱音声の自動アラインメント
3. ビート／セクション解析
4. 無音や低情報区間の提案
5. 自動リサイズ時の被写体追従
6. 翻訳字幕

すべてのAI機能で次を必須とする。

- 実行前に外部送信の有無を表示する
- 送信先と目的を表示する
- 元データを勝手に学習へ利用しない契約を確認する
- 結果を手で修正できる
- 失敗しても通常編集を続けられる
- AI機能を無効化できる

## 17. 停止条件と代替案

### WebCodecsでMP4書き出しが不安定

代替案:

- ffmpeg.wasmによる限定形式書き出し
- WebCodecsでフレーム生成し、別ライブラリで多重化
- 書き出し対応ブラウザをChromeへ限定

### 1080pプレビューが重い

代替案:

- 低解像度プレビュー
- プロキシ生成
- サムネイル／波形の事前計算
- エフェクトのプレビュー品質切替

### 10分素材でメモリ不足

代替案:

- 全フレーム保持を禁止
- ストリーミング処理
- チャンク単位のデコード／エンコード
- OPFSへの一時退避

### ブラウザ保存が不安定

代替案:

- `.dogaga`手動保存を早期導入
- 自動保存世代管理
- 起動時の復旧チェック

### 歌詞タップ同期が速くない

代替案:

- キー遅延補正
- 再生速度変更
- 行頭候補の自動スナップ
- 複数行の範囲伸縮
- 実操作ログからUIを再設計
