# DOGAGA 開発ロードマップ

更新日: 2026-07-17

## 1. 開発戦略

最初から完全な編集アプリを作らない。

DOGAGAでは、次の順に不確実性を潰す。

1. ブラウザで、実用的な速度と画質で再生・編集・書き出しができるか
2. タイムライン操作が気持ちよく成立するか
3. 歌詞同期が既存ツールより速く感じられるか
4. プロジェクト保存と復旧が壊れないか
5. 実際のMV／PV／Canvas制作で使えるか
6. その後に自動字幕、ビート解析、クラウド機能を足す

機能数ではなく、一本の動画が完成する縦の流れを優先する。

## 2. 技術方針（初期仮説）

### 2.1 対象環境

初期対象:

- デスクトップ
- macOS + Chrome最新版を第一基準
- Windows + Chrome / Edgeを第二基準
- 1080p、30fpsを基本
- 完成尺は10分程度までを初期目標

後回し:

- スマートフォンでの本格編集
- Safari / Firefoxの完全対応
- 4Kの安定書き出し
- 長時間／大量素材プロジェクト

### 2.2 推奨構成

候補:

- UI: React + TypeScript
- ビルド: Vite
- 状態管理: 小さく開始し、編集履歴を扱える構造を選ぶ
- デコード／エンコード: WebCodecs
- プレビュー合成: Canvas 2Dから開始し、必要箇所をWebGLへ移行
- 音声: Web Audio API
- バックグラウンド処理: Web Workers
- 作業キャッシュ: OPFS
- メタデータ: IndexedDB
- プロジェクト形式: バージョン付きJSON
- 補助変換: ffmpeg.wasmを限定的に検証
- テスト: Vitest + Playwright

WebCodecsは音声・映像コーデックへ低レベルにアクセスできるが、特定のコーデック実装を保証しない。最初に対応ブラウザと入出力形式を固定し、万能変換を目指さない。

### 2.3 ローカルファースト

MVPのコア編集は、ログインなし、サーバーアップロードなしでも動かせる構成を優先する。

- 元素材はFileオブジェクトまたはFile System Access APIで参照
- 波形、サムネイル、プロキシをOPFSへ置く
- 編集内容をJSONへ保存
- 素材はパスではなく、再リンク可能なアセットIDとメタデータで管理
- ブラウザキャッシュ消失に備え、`.dogaga`プロジェクトファイルを明示的に書き出せるようにする

### 2.4 プロジェクトモデル

最低限、次の構造を持つ。

```text
Project
├─ version
├─ canvas (width, height, fps, duration)
├─ assets[]
├─ tracks[]
│  ├─ video clips
│  ├─ audio clips
│  └─ text/caption clips
├─ markers[]
├─ styles[]
├─ exportPreset
└─ metadata
```

すべての編集操作をコマンドとして扱い、Undo / Redoへ接続できるようにする。

例:

- AddClip
- MoveClip
- TrimClip
- SplitClip
- DeleteClip
- AddTransition
- UpdateTextStyle
- SetCaptionTiming
- ShiftCaptionRange

## 3. フェーズ0: 土台と技術検証

目的: 実装方式の致命的な失敗を早期に見つける。

### 成果物

- 最小Webアプリ
- 動画ファイル選択
- フレーム表示
- 再生／停止／シーク
- 音声波形の簡易表示
- 1クリップのトリム
- 10〜30秒のMP4書き出し
- Chrome / Edgeでの動作記録
- 使用コーデック、ブラウザ、素材別の検証表

### 検証項目

- H.264/AAC MP4の読み込みと書き出し
- 可変フレームレート素材
- iPhone撮影素材
- 透過PNGとJPEG
- 音声のみのMP3/WAV
- メモリ使用量
- シーク精度
- 音ズレ
- 1080p書き出し速度
- ブラウザを閉じた場合の復旧

### 完了条件

- 30秒の1080p素材を読み込み、範囲指定し、音付きMP4で書き出せる
- 同じ入力と設定で、繰り返し概ね同じ結果になる
- 重大な音ズレがない
- 技術的に不可能／非現実的な形式を明文化できる

## 4. フェーズ1: 最小編集機

目的: 一本の短いPVを完成できるようにする。

### 機能

- メディア一覧
- タイムライン
- クリップ追加、移動、トリム、分割、複製、削除
- 再生ヘッドとズーム
- スナップ
- 画像の表示時間変更
- 音量調整
- フェードイン／アウト
- カット、クロスディゾルブ
- テキスト追加
- 16:9 / 9:16 / 1:1
- 720p / 1080p書き出し
- Undo / Redo
- 自動保存
- プロジェクト読み込み／書き出し

### 完了条件

- 10本程度の素材から1分動画を完成できる
- 保存してブラウザを閉じ、再開できる
- Undo / Redoで基本操作を往復できる
- 書き出し失敗時に原因と対処が表示される

## 5. フェーズ2: 歌詞エディタ

目的: DOGAGA独自の価値を作る。

### 機能

- 歌詞貼り付け
- 空行／改行による分割
- 行の結合／分割
- 再生しながらタップ同期
- 直前の同期を取り消す
- 行頭時刻一覧
- 開始／終了の微調整
- 次の行頭まで表示を自動延長
- 全行一括オフセット
- 選択行以降を一括移動
- 字幕一覧とタイムラインの相互選択
- 文字スタイルの一括適用
- SRT / VTT / LRCの初期対応

### タップ同期の想定操作

1. 楽曲を再生する
2. 歌詞パネルで先頭行を選ぶ
3. 歌い出しに合わせてSpaceを押す
4. 次の行へ自動移動する
5. 間違えたらBackspaceで一つ戻る
6. 終了後に波形上で微調整する

### 完了条件

- 30行程度の歌詞を10分以内に概ね同期できる
- 途中で停止／再開できる
- 全体の音ズレを一操作で修正できる
- 同期結果を字幕ファイルへ書き出せる

## 6. フェーズ3: 音楽向け演出

目的: 「簡単だが物足りなくない」状態へ進める。

### 機能

- ビート解析とマーカー
- クリップ境界のビートスナップ
- 文字アニメーション
  - フェード
  - スライド
  - ポップ
  - 文字送り
  - カラオケハイライト
- 簡易映像効果
  - モノクロ
  - 彩度／明るさ／コントラスト
  - グレイン
  - VHS風
  - グリッチ
  - ぼかし
- トランジション
  - ディゾルブ
  - 黒／白フェード
  - スライド
  - 軽いズーム
- プリセット保存

### 原則

効果を増やす前に、次を守る。

- プレビューが重くならない
- 書き出し結果と一致する
- 使う場面が説明できる
- パラメータを増やしすぎない

- セーフエリア
- 同一プロジェクトから比率違いを派生

## 9. AI機能の導入順

AIはMVP完成後に、明確な時間短縮が見込めるものから試す。

1. 音声からの字幕候補生成
2. 歌詞と音声の自動アラインメント
3. ビート／セクション解析
4. 無音や低情報区間の提案
5. 自動リサイズ時の被写体追従
6. 翻訳字幕

すべてのAI機能で、次を必須とする。

- 実行前に送信有無を表示
- 元データを勝手に学習へ利用しない
- 結果を手で修正できる
- 失敗しても通常編集を続けられる

## 10. 初期Issue候補

### 調査・設計

1. ブラウザ／コーデック対応表を作る
2. プロジェクトJSONスキーマを定義する
3. タイムライン編集コマンドとUndo設計

### 技術スパイク

6. WebCodecsで動画をデコードしてCanvasへ表示する

8. WebCodecsで音付きMP4を書き出す
9. OPFSへキャッシュを保存／削除する
10. 可変フレームレート素材の挙動を検証する

### プロダクト

11. 最小タイムラインを実装する
12. クリップのトリム／分割／移動を実装する
13. クロスディゾルブを実装する

## 11. リリース判断

### 技術試作通過

- 30秒の音付き動画を書き出せる
- 音ズレとメモリ問題の見通しが立つ

### Alpha

- 1分PVを作れる
- 保存／再開できる
- テキストとディゾルブが使える

### Private Beta

- 1曲分の歌詞動画を作れる
- Spotify Canvasを作れる
- 実制作で複数回使ってもプロジェクトが壊れない

### Public Beta

- 権利・プライバシー文書が整う
- データ削除と問い合わせ導線がある
- 対応ブラウザと制限が明記される
- エラー時に素材が失われにくい
