# ADR-001: 初期DOGAGAをデスクトップブラウザ専用に近い設計とする

- 状態: 採用
- 決定日: 2026-07-17
- 対象: MVPからPrivate Betaまで

## 背景

スマートフォン向け動画編集アプリは、CapCutをはじめ競合が多く、タッチ操作、縦長画面、端末性能、アプリストア配布、OS固有のメディア権限まで含めた別種の競争になっている。

DOGAGAが最初に作ろうとしている価値は、次のような編集体験である。

- 楽曲波形を見ながら映像を配置する
- 複数クリップをタイムラインでトリムする
- 歌詞一覧とプレビューを同時に見る
- 再生しながらキーボードで歌詞行を同期する
- ディゾルブや字幕タイミングを細かく修正する
- 一曲分のプロジェクトを安定して保存、再開、書き出しする

これらは、広い画面、精密なポインティング、キーボード、比較的大きいメモリとCPUを使えるデスクトップ環境との相性がよい。

## 決定

DOGAGAの初期ターゲットを、**パソコンのブラウザで動画編集するユーザー**とする。

### 第一対象

- macOS
- Google Chrome最新版
- マウスまたはトラックパッド
- 物理キーボード
- 1280px以上の横幅を推奨

### 第二対象

- Windows
- Google Chrome最新版
- Microsoft Edge最新版

### 初期の非対象

- スマートフォンでの本格編集
- タブレットだけで完結する編集
- タッチ操作だけで全機能を利用すること
- 狭い画面への完全レスポンシブ対応
- iOS Safari / Android Chromeでの安定書き出し保証

モバイル端末からページを開くこと自体を禁止する必要はないが、MVPでは「閲覧できる」と「編集に対応する」を明確に分ける。

## UXへの影響

### 同時表示を優先する

以下を一画面で扱えることを重視する。

- プレビュー
- メディア一覧
- タイムライン
- 楽曲波形
- 歌詞／字幕一覧
- 選択要素のプロパティ

スマートフォン向けに一画面一機能へ分断しすぎない。

### キーボードを第一級の入力手段とする

例:

- Space: 再生／停止、歌詞同期モードでは行頭記録
- Backspace: 直前の歌詞同期を取り消す
- S: クリップ分割
- Delete: 選択削除
- Cmd/Ctrl + Z: Undo
- 矢印キー: 再生ヘッドや字幕時刻の微調整
- Shift併用: 大きい単位で移動

すべてをショートカット必須にはしないが、頻繁な操作はマウスだけより速くできるようにする。

### 精密操作を妥協しない

- タイムラインの横方向ズーム
- 波形上の細かなドラッグ
- 数値入力
- 複数選択
- 範囲選択
- 右クリックまたはコンテキストメニュー
- ドラッグ＆ドロップ

タッチ操作へ合わせるために、これらを初期設計から外さない。

### 推奨環境を明示する

起動時またはヘルプで次を表示できるようにする。

- 対応ブラウザ
- 推奨画面幅
- 推奨メモリ
- 入力形式
- 書き出し上限
- モバイル編集が未対応であること

## 技術への影響

- WebCodecs、File System Access API、OPFS等について、まずデスクトップChromeを基準に検証できる
- モバイルブラウザのメモリ制限やバックグラウンド停止をPhase 0の必須条件から外せる
- 1080p、一曲分、複数素材という現実的な負荷へ集中できる
- UIを狭い画面向けに二重実装する必要がない
- Playwrightの主要ビューポートをデスクトップ中心にできる

## デザイン基準

MVPの主要ビューポート:

- 最小確認幅: 1280 × 720
- 標準設計幅: 1440 × 900
- 広い作業環境: 1920 × 1080以上

1280px未満では、編集画面を無理に縮小せず、次のいずれかを行う。

- 一部パネルを折りたたむ
- 推奨環境メッセージを表示する
- 簡易閲覧モードへ切り替える

## 将来のモバイル対応

モバイルフレンドリーは否定しない。ただし、デスクトップ版を完成させた後に、利用データと具体的な用途を見て判断する。

候補:

1. モバイルでプロジェクトを閲覧、プレビューする
2. 書き出し済み動画を確認、共有する
3. 字幕本文だけ修正する
4. Canvasの区間だけ選ぶ
5. 軽いテンプレート編集をする
6. タブレット向けの簡易編集画面を作る

デスクトップUIをそのまま縮小するのではなく、モバイルで価値のある操作を別途選ぶ。

## 再検討条件

次のいずれかが成立した場合に、この判断を再検討する。

- Desktop Private Betaが安定している
- モバイルからの利用要望が継続的に多い
- モバイル固有の明確な制作フローが見つかる
- ブラウザAPIと端末性能で、一曲分の編集が現実的になる
- モバイル対応がデスクトップ版の開発速度を損なわない

## 結果

### 得られるもの

- 競合が過密なスマホ編集市場との正面衝突を避けられる
- 歌詞同期、波形、タイムラインの快適さへ集中できる
- キーボードと広い画面を前提に、DOGAGA独自の操作を作れる
- 技術検証の範囲を現実的に絞れる

### 受け入れる不利益

- 初期ユーザー数は狭くなる
- スマートフォンだけの利用者には届きにくい
- 完全レスポンシブな製品としては開始しない

この不利益は、DOGAGAの中心価値を薄めずに完成させるための意図的な選択とする。
